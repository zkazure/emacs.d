#+title: Emacs Configuration

From now on my Emacs configuration will be stable and reliable.

However, there is still a long way to go.

* Package management

The configuration follows [[https://github.com/purcell/emacs.d][Purcell's]] modular style: =init.el= loads
=lisp/init-*.el=, and each module declares its dependencies nearby.
=early-init.el= enables package.el's normal startup activation.

=require-package= in =lisp/init-elpa.el= ensures installation, without
loading the library.  Installed packages, including built-in and archive
packages, are left alone.  Missing packages are installed from the declared
repository with Emacs's built-in =package-vc=:

#+begin_src emacs-lisp
(require-package 'helpful "https://github.com/Wilfred/helpful")
(autoload 'helpful-callable "helpful" nil t)
#+end_src

A package-vc specification plist can be used instead of the URL when a
repository needs options such as =:lisp-dir=.  For an explicit archive
exception, use =(require-package 'some-package :archive)=.  Installation
errors identify the package and source; they do not silently fall back to
another source.  Use =require=, autoloads and =with-eval-after-load= to control
when libraries load.

Direct package dependencies in the active configuration modules are declared
this way.  Package.el/package-vc resolves the packages' own dependencies;
these may still come from the configured archives.  Org's optional Babel
languages retain their existing =locate-library= checks.

Corfu, Vertico, Org-roam and Ghostel extensions use their parent package's
checkout.  Magit and Ghostel specify =:lisp-dir "lisp"=; the other extension
directories are added to =load-path= where needed.  Archive installations of
Embark split out =embark-consult=, so that package is installed from an archive
only when its library is missing from the existing installation.

The other explicit archive exceptions are AUCTeX (generated build files),
=cmake-mode=, =csv-mode= and =breadcrumb= (the existing archive distribution
is used instead of introducing additional source/build recipes).
Local VC packages retain their configured repository origins, including
personal forks.

Startup may access the network to install missing packages, but does not
upgrade existing ones.  When dependencies are installed, no network is needed
by this helper.  Upgrades remain explicit: use =M-x package-vc-upgrade= for a
VC package, or the package menu for archive packages.  Existing archive
installations are not automatically converted to VC installations.

This installs Emacs packages, not system tools, Tree-sitter grammars, fonts,
native module build dependencies or personal data.  Those still need to be
available for the associated features.  With existing packages, isolated
batch loading of the full configuration and its after-init hooks has been
tested, with server/auto-compile side effects disabled and personal data
paths redirected to temporary directories.  Helpful, GFM export, completion
mode activation, a real clangd hover request through Eglot/booster, and a
Pandoc conversion have also been checked.  GUI rendering and a complete
download/build of every package into an empty installation have not been
tested.  The helper's missing-package path was checked separately using an
isolated local Git package.

The helper's tests run with:

#+begin_src sh
emacs -Q --batch -L lisp -l tests/init-elpa-test.el -f ert-run-tests-batch-and-exit
#+end_src

* LilyPond

LilyPond support uses a user installation at
=~/.local/opt/lilypond-2.26.0=.  Install the official 2.26 archive there; its
=bin/lilypond= is preferred only by Emacs and its child processes.  When the
installation is absent, Emacs starts normally and reports that LilyPond is
unavailable.  Files ending in =.ly= and =.ily= load the bundled
=lilypond-mode= on demand.

Org Babel uses the same compiler; its PDF viewer and MIDI player commands are
configured as =xdg-open=.  Use =C-c '= to edit a source block in
=lilypond-mode= and =C-c C-c= to run it.  For example:

#+begin_example
#+begin_src lilypond :file scale.png
\version "2.26.0"
\relative c' { c d e f g a b c }
#+end_src
#+end_example

Change =:file scale.png= to =:file scale.pdf= for PDF output.
